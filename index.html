Stanford University • 1996–1998 Research Milestone

How MiniGoogle Works

In 1998, Stanford PhD students Larry Page and Sergey Brin published "The Anatomy of a Large-Scale Hypertextual Web Search Engine", forever changing how humanity retrieves information by treating hyperlinks as votes of confidence.

01 • Foundations

What is a Search Engine?

A search engine performs three core tasks: Crawling (discovering webpages via links), Indexing (storing words and link structures in a fast database), and Ranking (ordering matching documents from best to worst for a user query).

02 • Early 1990s Web

Traditional Keyword-Based Search

Early engines (like AltaVista and WebCrawler) ranked pages almost solely by counting query words using TF-IDF (Term Frequency–Inverse Document Frequency). Spammers easily exploited this by repeating hidden keywords hundreds of times ("keyword stuffing").

03 • The Breakthrough

What is PageRank?

Named after Larry Page (and web pages), PageRank measures a webpage’s objective importance using the web’s hyperlink graph. A link from Page A to Page B is interpreted as Page A casting a vote for Page B—weighted by Page A’s own importance.

04 • History

Who Developed PageRank & Why?

Developed in 1996 at Stanford University by Larry Page and Sergey Brin (initially nicknamed BackRub). It solved the crisis of low-quality spam results by leveraging human editorial judgment embedded in hyperlinks across the web.

05 • Probability Model

The Random-Surfer Model

Imagine a web surfer clicking links at random forever. With probability d = 0.85, they click a random outgoing link on the current page. With probability 1 - d = 0.15, they get bored and jump to any random page in the index.

06 • Mathematical Stability

What is the Damping Factor (d)?

Set to 0.85, the damping factor prevents "rank sinks" (pages with incoming links but no outgoing links) from trapping all probability mass and guarantees that iterative power-method calculations converge rapidly to a unique steady state.

07 • Link Mechanics

Incoming vs. Outgoing Links

More incoming links increase a page’s PageRank—especially if those linking pages have high PageRank themselves. However, if a page has many outgoing links C(Ti), its vote is divided equally among all targets.

08 • Search Architecture

Relevance vs. Importance

Relevance asks: "Does this page match the user's query words?" (Query-dependent). Importance asks: "Is this page a trusted authority?" (Query-independent). Modern engines combine both signals!

09 • The Master Equation

Classic PageRank Formula

PR(A) = (1 - d) / N + d · Σ [ PR(Ti) / C(Ti) ]

Where N is total indexed pages, Ti are pages linking to A, and C(Ti) is the out-degree of page Ti. Dangling pages redistribute PR / N to every page.

# app.py (Python Flask + SQLite + NetworkX Reference)
import sqlite3, math
import networkx as nx
from flask import Flask, request, jsonify

app = Flask(__name__)

def compute_pagerank_sqlite(db_path="minigoogle.db", d=0.85):
    conn = sqlite3.connect(db_path)
    cur = conn.cursor()
    pages = [r[0] for r in cur.execute("SELECT id FROM webpages")]
    links = cur.execute("SELECT source_id, target_id FROM hyperlinks").fetchall()

    G = nx.DiGraph()
    G.add_nodes_from(pages)
    G.add_edges_from(links)

    # Exact 1998 iterative PageRank with dangling node handling
    scores = nx.pagerank(G, alpha=d, tol=1e-6, max_iter=100)
    for pid, pr in scores.items():
        cur.execute("UPDATE webpages SET pagerank = ? WHERE id = ?", (pr, pid))
    conn.commit()
    conn.close()
    return scores
